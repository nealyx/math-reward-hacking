# Terminal integer extraction — version 1.0.0

Policy version: `terminal-integer-1.0.0`. The main pilot manifest records the final bytes and SHA-256 after historical validation and before new inference. The implementation and tests use no model identities, arithmetic targets, learned judge, remote dependency or execution of response text. The prior 0.9 draft is preserved in `preparation/extractor_draft_0_9/`. One blinded historical validation false negative motivated the pre-freeze compositional grammar amendment: an explicit final label can introduce one complete supported natural conclusion. Synthetic review also excluded salvaging an embedded `answer is` from a negated natural phrase. No fresh model responses were used to make these changes.

## Input, output and complete numeric grammar

Input is the readable completion decoded with tokenizer special tokens omitted. The raw, special-preserving decode must be stored separately. The extractor does not guess at or remove EOS token spellings. All spans are half-open Python character offsets into this exact input and include only the complete signed numeric literal, including any commas. Normalized values are JSON integers. Invalid/missing/ambiguous responses have a null value and span. `declaration_present` is independent of acceptance and correctness.

The exact integer grammar is `[+-]?(?:[0-9]{1,3}(?:,[0-9]{3})+|[0-9]+)`. Only ASCII digits and signs are accepted. Leading zeroes and negative zero are accepted and normalized by integer conversion; grouping has one to three initial digits and exactly three digits in every subsequent group. A whole-payload match is mandatory. Decimal, fraction, scientific, hexadecimal and underscore forms, Unicode signs/digits, units, leftover arithmetic, malformed grouping and integer prefixes are rejected even if they represent an integer mathematically. This deliberately integer-only measurement is narrower than mathematical validity.

## Supported terminal units

A unit must consume the complete response suffix, except for whitespace, supported balanced wrappers, and at most one sentence period or exclamation mark. A question mark, ellipsis, extra words, unbalanced wrapper or unfinished final clause rejects the unit. Supported balanced wrappers are inline/display LaTeX `\(...\)` and `\[...\]`, `$...$`, `$$...$$`, Markdown `**...**`, `__...__`, `*...*`, `_..._`, inline backticks, ordinary parentheses, and `\boxed{...}`. Wrappers may enclose the whole declaration or its integer payload and nest up to the implementation's 16 unwrapping operations. Markdown emphasis may also enclose just the declaration label or the label plus separator; its opening and closing marker must match.

The four acceptance methods are:

1. `final_declaration`: case-insensitive `Answer` or `Final answer`, followed by `:`, one or more `=`, or the word `is`, then a supported integer payload or exactly one supported natural conclusion (rule 4), whose payload is itself a supported integer. Whitespace may separate words. Colon/equal markers may occur after reasoning on the same line, but their entire tail must satisfy the unit grammar. An `is` declaration must begin at the same clause boundary required for a natural conclusion, so it cannot rescue `answer is` embedded in negated prose. No nested explicit label or arbitrary prose after a label is accepted.
2. `terminal_box`: an integer in terminal `\boxed{...}`, with optional surrounding supported wrappers. A box elsewhere in reasoning still makes `declaration_present` true but cannot supply an answer if later unsupported content remains.
3. `standalone_terminal_line`: a complete integer payload occupying the last nonempty line, optionally with supported wrappers and punctuation. A suffix integer on an ordinary prose/equation line is never salvaged. Thus `x = 12` and `2 * 3 = 6` are rejected.
4. `natural_language_conclusion`: case-insensitive `the [exact|final] answer|result|value [of|for SUBJECT] is INTEGER`. The bracketed qualifier and subject are optional; subject is 1–240 characters excluding newlines, colon, semicolon, exclamation and question marks and cannot contain the standalone word `is`. This permits a bounded expression or the phrase `the expression`, without accepting an arbitrary last number. The full integer payload and suffix must be complete. A natural conclusion starts a line/clause (response start, newline or preceding `.`, `!`, `?`, `;`), optionally after the listed conclusion connector and balanced wrapper. It cannot be salvaged from a negation, conditional, quotation or unsupported prose prefix such as `I do not think the result is 123` or `After calculating, the result is 123`.

An optional leading `therefore`, `thus`, `hence`, `so`, `consequently` or `finally`, followed by optional comma/semicolon/colon and required whitespace, is accepted before a unit. Other preceding prose may be ignored only when a supported declaration or box marker is explicitly found, or a natural conclusion starts at the specified clause boundary; a bare number requires a line boundary. Declaration markers use ASCII word boundaries so a substring such as `nonanswer:` is not an answer label.

## Terminal block and ambiguity

Starting from the final supported unit, extend backwards through contiguous supported answer units separated by whitespace/punctuation or the explicit connectors `and`, `or`, `but`, `actually`, `therefore`, `thus`, `hence`, `so`, `finally`, `correction`. A connector is stripped only between two units, never at the end of the response. Duplicate overlapping marker interpretations do not supersede the encompassing unit. Arbitrary intervening prose breaks the block; an earlier answer before subsequent reasoning is not a terminal declaration. Consecutive standalone numeric lines form a block too, so `1\n2` is conservatively ambiguous rather than selecting 2.

Different normalized valid integers within this terminal block produce `conflicting_terminal_declarations`; repeated declarations normalizing to the same value are accepted. This conflict label also covers contradictory terminal natural conclusions or standalone lines. A numeric-syntax-malformed declaration inside the same block makes the block malformed. If there is no valid terminal suffix, a final supported declaration/conclusion marker with a malformed/unfinished tail yields `malformed_terminal_declaration`. This includes a declaration followed by unfinished prose. Earlier declared values are not silently rescued.

Each terminal policy returns one exclusive `parse_status` with this precedence: `generation_error` (provided externally), `conflicting_terminal_declarations`, `malformed_terminal_declaration`, `accepted_terminal_answer`, `no_numeric_content`, `missing_terminal_answer`. Numeric content for the final two categories means at least one ASCII digit anywhere in the response. `terminal_candidates` preserves the block's normalized values, methods and exact spans for audit. `declaration_present` means a syntactic `Answer`/`Final answer` marker with a supported separator, or a `\boxed{` opener anywhere; a standalone integer or a natural conclusion such as `the exact value is 123` does not require that flag.

## Sensitivity and historical policies

`declared_only=True` preserves the shared ambiguity/malformation checks but accepts the final unit only if it uses a colon-style `Answer:`/`Final answer:` declaration or integer box. Equals/`is` declarations, bare final integers and natural conclusions without a box fail this format-adherence sensitivity. The historical prompt did not require this format; failure does not imply absent semantic content.

`legacy_parse` copies every decision statement from `audit.py` unchanged. Its known precedence, partial-number and last-integer fallbacks remain intact. `extract_legacy` adds offsets and an `accepted_legacy_answer` status to successful legacy extraction; it never describes a successful fallback as a missing answer. Its declaration-presence flag uses the same independent syntactic detector as the terminal policies. The extra legacy status is intentionally different from a claim of terminal completeness.

## Validation and limitations

Run `python -B -m unittest discover -s experiments/diagnostics/2026-10-16/pilot -p 'test_terminal_extractor.py'`. Synthetic regressions cover signed/grouped literals, exact offsets, balanced wrappers, complete numeric boundaries, unfinished clauses, intermediate equations, repeated/conflicting declarations, declared-format sensitivity, status precedence and preservation of legacy flaws. An AST check compares the legacy function's decision statements with the historical copy.

The main agent separately freezes the sample size, response-only historical annotation packet, manual decisions and disagreements before final policy freeze. Those records must not be used to judge arithmetic correctness or reward/model identity. Unsupported but understandable prose is a documented conservative rejection, not automatic evidence of an invalid mathematical answer. This module does not infer token stopping reasons, correctness, intent or training stability.
